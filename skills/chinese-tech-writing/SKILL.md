# 简体中文技术文档写作规范

本技能帮你写出读者能扫读、能照着完成任务的中文技术文档。核心是 Minimalism（Carroll 的极简主义技术写作）：先给行动与结论，只写当前任务需要的信息，更深的细节用链接渐进披露。下面的语法与风格规则都服务于这个目标。自检清单见 `references/quick-check.md`，STE 核心规则见 `references/asd-ste100-core.md`，三份规范原文见 `references/sources/`。

## 核心思想：Less is More（最小化写作）

读者一边学一边试，很少仔细读长文。落笔前先按 Carroll 的 Minimalism 原则组织内容：

- **先行动，后背景**：让读者尽快做真实任务；背景与原理放后面，或用链接。
- **只给当前需要的信息**：当前任务必需的写全，更深的细节用链接渐进披露。
- **少阅读、多行动**：一句一个意思，短句、短段、主动语态；标题与列表让页面能扫读。
- **具体示例优先**：可复制的命令、示例输出、默认值与边界，比形容词和原理管用。
- **帮助读者从错误中恢复**：写清前提、失败时的表现与下一步。
- **结构服务任务**：章节按读者完成任务的顺序排；固定模板只在项目有约定时沿用。

同一件事，写实现过程是`重构了摘要逻辑`，写读者能用的结果是`工作摘要限制在 500 字符内，超长内容在整句边界截断`。

## 语法

### 中英文混排

- 中文与英文单词之间留一个半角空格：`本文介绍如何快速启动 Windows 系统`。
- 中文与数字之间可加可不加，全文统一（推荐加）。
- 数字与英文单位间留空格（`16 GB`），与百分号、中文单位间不留（`6.5%`、`1000 元`）。
- 英文与全角标点之间不留空格：`他的电脑是 MacBook Air。`（不写 `MacBook Air 。`）

### 标点符号

- 中文语句用全角标点（`，。：；？！""''（）、《》`），整句英文用半角。
- 冒号：文档正文用全角`：`，软件 UI 字符串用半角`: `（如`错误: %1`）。
- 问号、叹号：文档用全角`？！`，UI 用半角`? !`；感叹号尽量避免、不得连用。
- 并列项用顿号`、`，即使并列项是英文（`Google、Facebook、腾讯`），最后一项可用`和`连接。
- 引用用全角双引号`""`，内层用单引号`''`；括号用全角`（）`，括号前后不加空格，括号内是纯英文或数字可用半角；括号加注时句号在括号外：`（见第 26 页）。`
- 文档正文省略号用`⋯⋯`（占两格六点，不用`...`或`。。。`），UI 用`...`；省略号不与`等`连用：写`香蕉、苹果、梨⋯⋯`或`香蕉、苹果、梨等水果`。
- 破折号占两个汉字位置`————`；数值范围用`～`或`—`：`132 kg～234 kg`，两数单位不同时都带单位；复合词与编号用半角连字符（`氧化-还原反应`、`图 1-1`）。

### 数字

- 一律半角数字；千位以上加千分号（`1,258,000`），4 位数可加可不加但全文统一。
- 货币用符号或中文名：`$1,000` 或 `1,000 美元`。
- 用`增加到`表示达到量，`增加了`表示增量；不写`降低 N 倍`，写`降低百分之几`。
- 量词具体：`两位研究人员`优于`2个研究人员`。

### 术语与英文

- 英文首次出现时括注中文：`IOC（International Olympic Committee，国际奥林匹克委员会）`，之后用缩写。
- 产品名、商标、键名不译：`Windows Server 2022`、`Visual Studio 2022`；`Ctrl、Alt、Enter、Esc、Tab`保留英文且不加`键`字。
- 缩写字母全大写；英文复数还原单数（`RAMs`→`RAM`）；英文书名、电影名改书名号《》。
- 同一术语全文同一译法（`app`→应用，`application`→应用程序；`select`→选择，`pick`→选取）。
- 进行中的动作用`正在…`（`Uploading…`→`正在上载…`），章节标题的`Using…`译`使用…`。
- 方向键译`向左键、向上键`；快捷键写作`退出(&E)`，放在标点之前：`搜索(&S):`。
- 时段划分：凌晨 0:00–5:59、上午 6:00–11:59、中午 12:00–12:59、下午 1:00–17:59、晚上 18:00–23:59。

## 风格

- 像跟同事说话，不像写公文：用日常用语，少用书面腔（`倘若`→`如果`，`总而言之`→`总之`，`至`→`到`）。
- 句子短：无标点单句 20 字以内最佳，超过 40 字不可接受；长句拆开，用简单句与并列句，不堆长定语。
- 肯定句、主动语态：`请确认装置的电源已关闭`；不写双重否定。
- 段落一个主题，中心句放段首，不超过 7 行、6 句，4 行以内最佳；段间空一行，段首不缩进。
- 用`你`不用`您`；不用`给力`、`酱紫`、`童鞋`等网络流行语。
- 不用`最好`、`最强`、`唯一`这类绝对化形容；泛指时避免`他`，不用`剩女`、`老外`等歧视性词汇。
- 正确使用`的/地/得`；少用`的`，一句话里出现两三次就删；代词指代唯一明确，能省略就省略。
- 无障碍语境用`选择`代替`点击`。
- 翻译先理解整段意图再重组，不逐词直译；删掉不影响含义的修饰语。

## 结构

- 标题最多四级，一级标题下不能直接出现三级标题，下级标题不与上级同名；同级只有一个就不设层；尽量不用四级标题，改用加粗列表。
- 标题末尾不加句号、逗号、顿号（问号、叹号、书名号可以）。
- 文档按`简介 → 快速上手 → 深入`组织：先回答是什么和怎么开始，再展开环境准备、安装、配置、进阶、API、FAQ、附录。教程、指南、参考与 FAQ 同属文档站内容，都按读者的使用路径排列。
- 文件名小写、半角、连词线分隔（`advanced-usage.md`）；`README`、`LICENSE`可大写；文件名不用中文。

## 特殊文档类型

### README 与发行说明

特殊约束在顺序。README 按读者决定是否使用的顺序组织：

1. 定位：给谁用、解决什么问题，一两句；可以补适用对象与边界。
2. 开始：前置条件、可直接复制执行的命令、预期结果。
3. 配置：默认值、生效条件、失败时的行为；参数多时用表格。
4. 限制：不支持什么、需要什么条件、已知问题。
5. 深入：架构、部署、FAQ；放不下就链接到 `docs/`。

README 是长期文档，只放稳定信息；版本专属信息写进发行说明。

发行说明按读者决定是否升级的顺序组织：先写相对上一个正式版的差量，再写需要行动的变化（给替代方案或迁移路径），其余按变化大小排列。需要备份或多步迁移时写清顺序与不可逆操作。只写读者能感知的行为，不写实现过程；篇幅服从信息量，没有内容的段落不保留；必须披露未验证能力时写清未验证范围。

### UI 文案与错误消息

- 先说结论或问题，再说动作；一句话一个意图。
- 用句子片段更干脆：`步骤如下：`优于`请执行以下步骤：`；`如图所示：`优于`请参阅下面的图像：`。
- 错误消息用标准短语：`无法…`、`内存不足`、`无法使用…`；占位符`%d`、`%s`不可改写，翻译后保证语法通顺。
- 语气温和，不指责用户，不说教。

### 简明写作：STE 的受控语言思想

STE 用受控词汇与简单句实现简明，是简明技术中文的参考方案，核心思想适用于中英文：一词一义、术语全文一致；用简单时态与主动语态；一句一个动作，条件前置；同一个概念只保持一种写法。操作步骤与安全提示也按这个思路写：每句一个动作，Note 只给信息不带指令，WARNING 写人身风险、CAUTION 写设备风险，并给出条件与后果。完整词汇表与 53 条规则只在明确要求 STE 合规的英文文本中使用，见 `references/asd-ste100-core.md`。

## 冲突裁决

- 场景优先：文档与 README 用文档规范（全角标点、`⋯⋯`），软件 UI 字符串用软件规范（半角冒号、`...`）。
- STE 规则只用于明确要求 STE 合规的英文文本；其他文本取其简明思想，不套用词汇表。
- 一致性：规范允许可选时（数字空格、4 位千分号）选一种并全文坚持。
- 可读性高于字面对应：直译生硬时重写，不逐字对应；省略号与`等`、`至`等具体冲突按语法硬规则执行。

## 交付前自检

写完按顺序检查一遍，细节见 `references/quick-check.md`：

1. 读者能从首句知道文档解决什么问题、下一步做什么。
2. 排版：中英文空格、全角半角标点、数字千分号。
3. 句子：长句拆短、否定改肯定、被动改主动。
4. 用词：`您`→`你`、术语首现括注、产品名与键名未翻译。
5. 结构：标题层级合法、一段一个主题、文件名合规。
6. 特殊文档：README 与发行说明按决定顺序检查。
